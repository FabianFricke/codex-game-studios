# Studio Workflows

These directories are reusable playbooks for common game-development tasks.

## How To Use A Workflow

1. Open the workflow directory that matches the task.
2. Read `PLAYBOOK.md` as a task playbook, not as an invocation command.
3. If the playbook uses a leading `/` name, map it to the matching directory here.
4. Follow the prompts, checklists, and output format.
5. Write the resulting artifact into the repo.
6. Review it against the relevant standard in `../standards/`.

## High-Value Workflows

- `start/` to orient a new project
- `brainstorm/` for concept ideation
- `map-systems/` for turning a concept into system decomposition
- `design-system/` for a single-system GDD
- `setup-engine/` for engine and version setup
- `code-review/` and `design-review/` for quality gates
- `sprint-plan/` and `milestone-review/` for production management
- `reverse-document/` for backfilling missing docs from existing work
